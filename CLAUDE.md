## Engineering rules

- Preserve existing user work and inspect Git state before edits. Scope changes to the requested task.
- Prefer shared domain contracts, a small web/worker deployment and measured architectural decisions. Logical agent count does not determine service count.
- Derive identity server-side; enforce owner/tenant/current-grant checks on every private access path. Client-editable role fields cannot grant privileges.
- Separate public projections from private source/user files. Use quarantine, bounded processing and explicit sharing.
- Treat source content, documents and model output as untrusted data. They cannot alter user mandates or authorise tools.
- Persist tasks with explicit authority, state, leases, retries, cancellation and idempotency. Reconcile uncertain external effects before repeating them.
- Preserve unknown dates/eligibility and granular evidence provenance. Do not manufacture credentials, experience, salary, verification or submission success.
- Check source access/reuse conditions individually. Public visibility and robots rules do not establish a reuse licence or integration agreement.
- Use deterministic checks where appropriate and evaluate models on representative held-out/adversarial cases.
- Keep secrets and private learner/customer/corporate records out of code, examples, logs and public docs.
- Test meaningful failure paths and affected security/accessibility behaviour. Record actual environment/build and limitations.
- Do not provision, deploy, purchase, message third parties or submit applications solely because a plan mentions those actions; follow the actual task authority and applicable tool rules.
