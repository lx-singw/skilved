Hosting, scheduling and automatic publication remain undeployed/unqualified. There are no real AI calls, live cloud writes, quota changes or live source/role/authority changes. Employer email/intake verification remains unsupported.

## Versioned authorization and retained holds

`automation.missingDateEvidence: "shadow_v2"` requires the existing missing-date conditions: shadow mode, original verification, explicitly enabled employer crawling and rejected undated admission. It additionally requires `originDiscovery: "shadow_v1"`, which requires the shadow issuer registry and no inline issuer list. It is an explicit Source-role/revision choice. Absent configuration and `shadow_v1` retain their existing no-probe behavior for unqualified missing-date routes; staging retains crawl off.

Only a failed missing-date preflight with one supported portal, supported category/programme scope and absent or explicitly unspecified timing can trigger the new probe. The resolver's existing exact destination, robots, byte, DNS/TLS, pacing, source/grant/lease and authority fences apply. It may fetch a corporate careers page only through current reviewed corporate authority. It does not guess a corporate domain, fetch a hint's unreviewed corporate website, expand a tenant, remove tracking queries or infer authority from a mailbox.

In the V2 evidence path only, a whole bare field label followed immediately by `Not specified` or `Not stated` is supported, including a two-cell table rendered as `Closing date` and `Not specified` on separate lines. The exact two-line quote is retained. Intervening fields, duplicate timing, extra timing prose and malformed dates remain held. V1 evidence and both existing undated-draft policies keep the prior parser behavior; this is not a new undated admission rule.

Existing reviewed corporate delegation can be found and reused across jobs, with parent revision/expiry checks and one current proof version. Probe bodies are reused for exact original verification rather than fetched twice. Unknown issuer hints create bounded `needs_evidence` observations through the existing employer-onboarding workflow; an onboarding need is not an approved corporate identity. Existing Source-role identity review and corporate-to-portal delegation are still required.

Missing-date original assessment receipts use `missing_publisher_date_v2` and retain source timing, snapshot/hash provenance, unverified availability, held admission and no publication. Origin receipts retain acquisition failures separately. For this evidence-only path, an unavailable probe does not replace the original publisher precision error or claim closure. The preflight exception/cooldown remain, with zero model admission. Grant and authority revocations still propagate rather than becoming acquisition outcomes.
