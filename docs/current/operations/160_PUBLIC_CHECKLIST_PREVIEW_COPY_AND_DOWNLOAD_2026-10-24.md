## Behavior and privacy boundary

The server passes only the public ID and validated public origin to the client controls. Without explicit trusted origin configuration, controls stay disabled. The disposable fixture supplies a synthetic HTTPS origin only to its owned child process; no actual deployed hostname, production configuration or release authority is established.

Every preview, copy or download starts a new public read. Previous output clears immediately, duplicate intents are serialized, and teardown aborts pending reads and prevents late native effects or success messages. A preview never authorizes a later copy. Each mounted control instance owns a disposable controller, including development effect remounts. Already handed-off clipboard/download operations cannot be recalled on unmount; the UI makes no recall or delivery claim.

The selectable read-only preview and each native effect use the same fresh public payload. Copy success is announced only after the clipboard promise resolves. Unsupported or denied clipboard access retains the public preview for manual selection without echoing host errors. Download creates a UTF-8 plain-text Blob, uses the formatter's public-only filename, removes its temporary anchor and releases its object URL. Its notice says a download was requested and directs the reader to browser downloads; it does not claim a file was saved or delivered.

Restricted/closed/unavailable fresh results retain only a dated canonical reference, without previous checklist facts or the official destination. Initially unavailable/status-only detail pages retain their existing safe view. The public component/controller/adapter dependency graph imports public preparation code only; it does not read ticks, local progress, annotation or receipt stores. No analytics, persistence write, recipient or messaging endpoint is added. Readers are told that a copy can become stale, does not submit an application or back up personal progress, and that links may use data.
