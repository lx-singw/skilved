## Application-method correction

Before this change, a bare next-line email was recognized only after the exact send-email phrase already supported by the parser. The new case instead has an explicit CV/document submission instruction. Under an immediately preceding application heading, the parser now accepts a bounded explicit email/send/submit instruction ending in a recipient marker and followed by valid email addresses. It preserves the complete source block and original recipient spelling.

Consecutive explicit recipients remain separate candidates; they cannot silently become one approved method. Existing route-count limits still apply. Missing application headings, enquiry/form-request wording, negation, reference contacts, physical submission instructions, URL-like instructions and invalid address layouts are excluded. An extracted email remains pending and requires registered issuer checks; it does not authorize email sending or publication.

The source-hold policy advances from version one to two, allowing a future scheduled job to reconsider an older negative parse before its original time limit. Old entries are preserved and become inapplicable by version, rather than being deleted, extended or refunded. The published-watch regression uses a current-version hold so that it still exercises the watch bypass. Extraction/validation instructions, schemas, model chain, token limits and publication criteria are unchanged. A candidate fingerprint changes when its parsed method changes; unrelated source facts are not rewritten.
