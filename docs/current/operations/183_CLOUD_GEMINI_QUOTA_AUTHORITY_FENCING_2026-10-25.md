# Cloud Gemini quota-authority admission

25 October 2026. Cloud Gemini workers now require an explicitly bound quota authority before scheduling, claiming, fetching, reserving calls or writing results. This prepares the handoff from the local shared ledger to the persistent staging database. **Authority has not transferred:** staging remains an inactive replica, and hosting remains undeployed at the user's request.

## Worker enforcement

The [authority module](../../../packages/catalogue/src/ai/gemini-authority.mjs) requires the worker's configured catalogue project and actual database project to agree. Cloud workers must additionally supply `SKILVED_GEMINI_AUTHORITY_PROJECT` matching that project and a 64-character lowercase hex `SKILVED_GEMINI_AUTHORITY_EPOCH`. An explicitly configured demo emulator can omit authority for isolated regression work; supplying authority settings also enables enforcement there. A partial or mismatched binding fails closed.

The record is `m0_model_authorities/<provider-scope-hash>`, with one `json` field containing a version, provider, database project, scope, epoch, active/revoked status, migration and original ledger hashes, and activation time. Strict parsing rejects absent, malformed or future records and missing provenance fields; revoked records and mismatched epochs, projects or scopes reject stale workers. Activation must independently verify the referenced migration and ledger: the runtime validates their hash format, not the entire imported history on every transaction. The provider project determines quota scope independently of the database project. This change does not change model order, configured limits, daily reset rules or fallback behavior.

The [RecentJobs worker](../../../packages/catalogue/src/recentjobs-worker.mjs) checks that record inside every Gemini worker transaction, before source/grant admission and before the operation's writes. Source budgets, jobs, shared usage and cooldowns stay in the same database; authority does not permit separate quota and job stores. The existing source grant, shadow mode, source revision, lease and allowance checks still apply. A quota-authority record by itself cannot authorize execution or publication.

The [staging launcher](../../../deployment/catalogue-staging/runtime/guards.mjs) requires authority settings before SDK initialization. Its [job template](../../../deployment/catalogue-staging/worker.job.yaml) remains disabled with an invalid epoch placeholder. The [history importer](../../../packages/catalogue/src/staging-migration.mjs) now rejects any existing quota-authority record, preventing inactive-history replay after operational authority is introduced.

## Verification and preserved state

Six new offline tests cover configuration, independent provider scope, emulator restrictions, strict record parsing, revoked/stale bindings and cloud worker rejection before grants or effects. Three real-emulator worker tests cover missing/revoked/stale admission, revocation during request pacing before any source fetch, and two independent workers racing for the same final provider allowance. Exactly one call is admitted; a later epoch change blocks another call without changing usage. Existing migration coverage now also rejects authority-bearing targets. Staging launcher checks include missing, wrong-project and malformed authority settings.

All **962 catalogue tests pass** on the complete rerun. A separate focused run passes 24 tests, including the five staging launcher checks. The rebuilt worker image runs as `node`; two container executions with networking disabled reject disabled activation and missing authority before SDK startup. The image is not deployed. The first full run passed 961/962 and exposed a new synthetic cloud test inheriting the emulator endpoints; its configuration guard correctly rejected that environment before the test's intended admission check. The fixture now explicitly removes those inherited endpoints. This is a test-isolation correction, not a relaxation of cloud configuration checks. The original failure evidence is retained privately.

A separate read-only cloud process verifies all **385** imported records and their raw manifest fields, the unchanged receipt and connectivity marker, and the absence of quota-authority records, worker/operator grants, queues, leases, watches and public listings. The private operator uses the existing gcloud user's short-lived token only in memory. This does not verify a hosted workload identity. No cloud writes, source requests or provider calls occur.

The local ledger remains byte-unchanged at **151 requests, 458,579 known tokens and 72 unknown usages**. All prior private artifacts, five accepted review drafts, two private assessments, immutable origins, source caps and historical expiries are preserved. The current source-day counters retain CNH 12/12 and Motus 6/6 until their existing reset; accepted expired decisions stay expired. No provider exhaustion, cache, hold or allowance is cleared.

## Cutover still required

This fence covers the current managed `RecentJobsWorker`. It cannot recall a network request already admitted by a committed reservation, stop direct API-key calls, enforce older code or retire arbitrary manual experiments. Explicit demo emulators remain available for synthetic tests. Before actual cutover, stop and drain every old caller, reconcile outstanding reservations and the complete authoritative ledger against the replica, retain an immutable checkpoint, and create the reviewed authority record. Route all managed callers to that database and epoch, and retire/fence old experiment entry points. Do not infer authority transfer from copied counters or from the environment settings alone.

No authority record, worker grant, provider secret permission, cloud job, scheduler, billing link or feed publication is created in this sprint. The local runtime remains authoritative. Next perform that reviewed cutover, then verify the attached ingest-only identity and obtain bounded fresh normal-writer evidence after the existing allowance reset. Hosting remains undeployed, employer crawling optional/off, Gemini shadow-only and production publication disabled.
