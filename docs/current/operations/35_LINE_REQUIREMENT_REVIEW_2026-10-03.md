## Line contract

`line-requirement-review.mjs` exposes `recentjobs_requirement_review_v4`. It reuses V3's code-owned scopes and conditions without changing V1–V3 contracts, selectors or hashes. Code-owned passages never appear in the model's output keys. The whole numbered source remains visible; claims, expectations and application destinations remain absent.

Every residual line has a required `L<number>` property under `lines`. Its value is a non-current applicability string, a current condition object containing kind/strength/group/relation, or an integer continuing the immediately preceding condition/unknown passage from its first line. Local checks reject chained, non-adjacent, context, future and cross-segment continuation references. JSON property order does not determine source order. Code reconstructs spans, copies exact source text and retains canonical group/alternative logic through the existing compiler.

Missing headings now violate the provider schema itself rather than only a local passage-partition check. This is a contract constraint, not evidence that the provider successfully generates this format. Current metadata remains required and non-null; non-current values carry no metadata. Model groups remain 1–19, with group 20 reserved for code-owned independent ALL conditions. Known multi-line alternatives and unresolved scopes remain exact; unclear strength is distinct from unclear applicability. The instruction also distinguishes engineering course/N1/NATED qualifications from standalone school subjects.
