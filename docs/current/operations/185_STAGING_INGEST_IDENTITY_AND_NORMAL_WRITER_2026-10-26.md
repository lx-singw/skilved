# Staging ingest identity and normal draft writer

26 October 2026 (SAST). A real CNH notice has completed the normal RecentJobs worker against the persistent default database in `skilved-staging`. The worker retrieved the notice, called Gemini for extraction and validation, and saved revision 2 of the existing private CNH draft. Hosting remains undeployed at the user's request; nothing was published.

## Verified identity and temporary access

The [identity verifier](../../../packages/catalogue/src/worker-identity.mjs) accepts a trusted backend authentication client for local delegated checks, while hosted execution continues to use ADC by default. Both paths require token verification for the project-specific audience and a service-account email with boolean `email_verified: true`. Missing or invalid configuration rejects before requesting credentials, and authentication failures expose only `WORKER_UNAUTHORIZED`. Environment email hints do not establish identity. Tests inject a verifier; the real staging check used Google's default cryptographic verifier.

The operator temporarily received Token Creator on the existing staging worker service account only, through a conditional binding expiring after 45 minutes. No project-wide role, downloaded service-account key, global ADC file or provider-secret permission was added. Delegated access tokens were requested with a 900-second lifetime and kept in memory; ID tokens follow Google's token lifetime. Revoking delegation does not recall an already issued token. The check separately verified the ID token's signature, audience and email, and a Firestore read/write using that delegated service account. This proves delegated identity and database access; attached Cloud Run identity remains untested while hosting is off.

An initial attempt and two diagnostic checks stopped at IAM Credentials `getOpenIdToken` permission denial, without creating an ingest grant, fetching a source or calling Gemini. All temporary bindings were removed after those attempts. The eventual successful attempt included bounded token-readiness handling before worker activation. The permission-policy check had already passed during the failures; propagation is a plausible explanation rather than a confirmed root cause. Google documents [eventual consistency of IAM changes](https://docs.cloud.google.com/iam/docs/access-change-propagation).

A source-scoped, ingest-only application grant expired after 15 minutes. Its job identifier was audit metadata, not a job-level authorization boundary. The operator explicitly invoked one normal detail job, with a fixed two-call ceiling; it did not start discovery or a worker loop. The [worker admission check](../../../packages/catalogue/src/recentjobs-worker.mjs) now rejects malformed or expired optional grant timestamps in every transaction, comparing actual instants so fractional-second formatting cannot bypass expiry. Existing grants without an expiry remain supported. Expiry during an admitted request never refunds the reserved allowance.

Cleanup disabled the application grant and removed the exact conditional IAM binding, preserving the earlier policy. Independent read-only verification found no active ingest grant, queued job, held worker lease or public record. The inactive grant and completed job remain as evidence.
