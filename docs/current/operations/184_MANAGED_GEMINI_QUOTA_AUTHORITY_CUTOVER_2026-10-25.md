# Managed Gemini quota-authority cutover

Started 25 October 2026; handoff verified 26 October 2026 (SAST). Managed Skilved Gemini quota authority has moved from its local ledger to the default persistent database in `skilved-staging`. This does not activate a worker, deploy hosting or publish a feed entry. The original local ledger remains byte-identical as a retired historical snapshot.

## One route for the shared provider scope

The [reviewed routing policy](../../../packages/catalogue/src/ai/gemini-authority-routes.mjs) binds Skilved's existing provider scope to the staging project, default database and current epoch. These are deployment identifiers, not credentials or an execution grant. A current worker cannot move that scope back to an emulator, use a named database, choose another project or supply an older epoch. The provider scope remains independent of the Firestore project; migration never rebases usage to the staging project.

The [transport fence](../../../packages/catalogue/src/ai/gemini-authority.mjs) adds request-local admission context after the worker's quota reservation transaction commits. Gemini's native transport always requires that context. Registered scopes require it even with an injected transport, so a standalone helper or handwritten `runAttempt` callback cannot accidentally bypass accounting. Concurrent attempts keep separate context, which is removed when their callbacks complete or throw. Unregistered mock transports remain available for synthetic regression tests. The [provider adapter](../../../packages/catalogue/src/ai/gemini.mjs) checks admission before invoking the transport; unauthorized attempts do not become provider failures or trigger availability fallback.

The extraction and emulator-shadow help text now explains that live Gemini calls belong in the managed worker. Environment variables alone cannot create admission, authority or a source grant. Groq behavior and offline response evaluation are unchanged.

## Atomic handoff

The [cutover module](../../../packages/catalogue/src/gemini-authority-cutover.mjs) accepts only the default staging database, an independently reviewed migration manifest and original ledger hash, the registered routing policy and drain evidence no more than ten minutes old. It checks every imported raw document and ID, source binding, spent budget, quota row, cooldown, migration receipt and absence of operational grants, queues, leases, watches or public records. It repeats those checks inside the write transaction.

The only new cloud documents are the provider-scoped active `m0_model_authorities` record and an immutable `m0_model_authority_handoffs` receipt. The receipt binds the epoch, migration/ledger hashes, original quota totals, source bindings and local drain evidence. All 385 history documents and the original inactive-import receipt remain unchanged. A conflicting or partial handoff rejects without overwrite or deletion. An exact immediate retry verifies read-only; it cannot create missing authority in the separate verification process. The ten-minute drain and existing 24-hour migration-review windows also apply to this bounded replay API.

The known-host drain inventory checks Linux runtimes, Docker containers, Windows Node/Python processes and local Codex automations. Unrelated Codex tool servers are identified separately; the existing Skilved sprint automation is already paused. Known reservations and the ledger export predate both worker leases and provider timeouts by hours. Missing historical call receipts and unknown token usage are preserved rather than invented or refunded.

After activation, a separate process verifies the full history, authority and handoff. A worker admission probe reads the active authority successfully but still fails `WORKER_FORBIDDEN`: no ingest grant exists. That probe uses the operator-authenticated Firestore client with the expected principal string; it is not proof of a verified attached workload identity. Neither the probe nor the handoff fetches a source or calls Gemini.

The local handoff pointer records the authoritative project, database, epoch and remote record paths. It marks the unchanged local ledger as retired; the original snapshot becomes owner-read-only (`0400`), with a non-root write-access denial checked. The pointer is private operator evidence; runtime enforcement comes from committed routing and transactional database admission, not an optional local file.

The initial failure and emulator logs are retained; its precise intermittent cause remains unconfirmed.

The real cloud transaction creates exactly two records. Separate-process read-only verification checks all 385 history documents, the immutable import receipt, new authority/handoff and absent execution grants/queues/public records. The historical ledger remains **151 requests, 458,579 known tokens and 72 unknown usages**. Five original review drafts, two private assessments, source caps, undated origins and accepted review-expiry times remain unchanged. The South African source day rolls over naturally during verification; the earlier day's spent rows remain intact. Expired accepted decisions remain expired; a quota handoff does not renew source freshness or establish current application availability.

This is enforcement for current managed code and the known callers inspected on this host. It cannot recall an already admitted network request, revoke the API key, stop direct HTTP calls outside this runtime, inspect other hosts or control older external checkouts. Those require separate operator controls; no global provider-account lock is claimed. Authority changes must still stop/drain callers and reconcile outstanding reservations before rotating epochs.

There are no new worker/operator grants, reconstructed queues, provider-secret permissions, cloud jobs, schedulers, billing links or public records. Hosting remains undeployed at the user's request, employer crawling optional/off, Gemini shadow-only and production publication disabled.
