# Source-bound guidance for complete location evidence

Date: 18 October 2026. Status: extraction receives advisory source passages and, where suitable, a contiguous range covering those passages. The location evidence and completeness guards remain unchanged. This sprint uses offline regressions and saved-answer replay only; it makes no source requests or provider calls and changes no real draft, quota record or publication state.

## Input guidance and contract versions

The preceding [guarded full-Flash repeat](110_GUARDED_FULL_FLASH_REPEAT_2026-10-18.md) retained both ALPLA location values but cited only the work-base sentence. New `locationSpanHints` supplies exact recognised source text with one-based inclusive line ranges, plus an optional `enclosingSpan`. It supplies no structured city, province or country values. The model must read the source, retain every supported place and select its own complete evidence; quote-based output must include all intervening text rather than concatenate separate passages.

Recognised passages reuse the existing narrow affirmative work-base and typed location policy, and add conservative inline or two-line location labels. Generic labels in recognised contact/residence contexts are suppressed. Multiline lists, unknown/alternative values and unsupported layouts may produce no hint. Programme hints use the selected intake's scope while retaining original parent line positions. A suggested range cannot bridge excluded promotion/preparation lines, scope gaps or the 4,000-character quote limit. Differing generic label values suppress the enclosing range. These are bounded advisory checks, not a geographical classifier, exhaustive conflict detector or proof of completeness.

Ordinary compact extraction, split metadata, native Gemini and programme extraction receive the guidance. Canonical and programme extraction advance to V17; compact extraction becomes V17/compact V7 and split metadata V10 so changed inputs do not reuse older extraction cache entries. Output schemas and the compact V7 wire grammar stay unchanged. Ordinary validation remains V13 and programme validation V12, with unchanged validation contracts. Provider selection, fallback policy, quotas and token/time limits are unchanged.

Both existing location guards still check the returned answer. Code does not fill missing place values, infer geography, widen returned spans, repair a response or retry a semantic failure. A null suggested range does not mean location is unstated, and a non-null range does not establish coverage, attendance, relocation or employer verification.
