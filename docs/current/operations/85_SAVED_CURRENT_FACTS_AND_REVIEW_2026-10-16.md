## Implemented result

Saved entries read validated current public ID, revision, title and publication state. Public summaries stay in component memory, with no cached application destination or persisted source facts. A different revision on the same identity displays a change notice; this also covers a lower revision rather than incorrectly assuming every change is newer. Only an explicit action on the actual detail page marks its displayed revision reviewed. Mount, refresh, focus and navigation never acknowledge it automatically.

Acknowledgement uses the existing atomic local command, preserving first-save time, personal stage, Applied-report time and route history. A competing local edit rejects a stale acknowledgement instead of overwriting the other person's browser action. Committed feedback distinguishes reviewing details from saving or applying. An acknowledgement concerns the displayed detail version; a later server change is detected on the next public read, and the unchanged server guard still rechecks an application handoff.

Each saved entry has an explicit public-detail check. Focus, pageshow and becoming visible also refresh current summaries. A refresh aborts its previous request, clears the displayed summary while checking and ignores results from aborted requests; these effects only read. Closed, restricted, missing and unavailable states retain annotations, offer current-detail/retry navigation and never activate a cached application link. Restricted and unavailable detail pages link back to saved references. Missing and unavailable remain different states.

The existing server lookup resolves confirmed aliases and stops redirecting reversed decisions. When the returned ID differs, the saved entry explains that it currently resolves elsewhere and links to that listing. It does not compare revisions belonging to different IDs, rewrite the saved ID, acknowledge that other ID's revision, delete annotations or silently save the target. If both IDs are saved, the UI explains that both sets of progress are retained separately. This is preservation and explanation; explicit annotation reconciliation is still pending.
