## Versioned evaluation rule

`packages/catalogue/src/ai/repeat-evidence.mjs` exports `inspectRepeat` and `recentjobs_repeat_evidence_v2`. Future evaluators can import this shared policy instead of copying a private helper. The worker, model prompts, V27 extraction, V15 assessment, production caches and publication gates are unchanged. The evaluator performs no fetches or writes and always reports publication and qualification false. It compares trusted supplied canonical records, source data and client receipt history; it does not independently establish their authority or current vacancy availability.

The only equivalence requires all of the following:

- One source-owned HTTPS portal route, without URL credentials, explicit non-default port or fragment, and a standalone exact source line for its generic label.
- Both stated application facts retain exactly that destination, method and original instruction.
- One practical fact exactly repeats the generic label as both value and evidence; the other is explicitly `not_stated`, with null value and evidence.
- The label is exactly one of `Apply now online`, `Apply online`, `Apply now` or `Click here to apply`.
- No physical submission finding, multiple routes, unresolved programme subjects or per-programme scope.
- All other compared material facts and requirement logic still match, and source, receipt, checklist, semantic and accepted-state preservation checks pass.

The comparison result records both `strictMaterialCoreEqual` and the effective `materialCoreEqual`, plus an explicit `generic_portal_direction_duplication` difference when used. Only comparison views omit the acknowledged duplicate. Input records, evidence and source text are never normalised or repaired.

## Boundaries retained

Changed vacancy paths or queries, email methods, clipped route evidence and absent source-written instructions still fail. Actual document submission, email subjects, recruitment references, time limits, extended application instructions and uncertain practical facts cannot be dropped under this rule. Neither case folding nor approximate matching broadens the generic label list.

Canonical record validation precedes material comparison. Issuer, title, category, intake, location, residence, experience, audience stage, fields, organisations, compensation, practical wording, requirement kinds/levels/values/evidence and ALL/ANY/IF logic remain material. Requirement IDs and commutative child order are compared independently of generated naming; summary wording and bookkeeping IDs remain outside material equality. Empty or changed accepted-state evidence and missing prior-receipt inventory fail rather than counting as preservation.

Freshness still needs distinct new successful extraction and validation receipt IDs with matching stage, provider, model and request hash, relative to the supplied prior inventory. Cached, reused, duplicate, failed or mismatched receipts fail. An identical request hash can belong to a genuinely new client receipt; hash novelty is not substituted for request evidence. A matched frozen source, a passing checklist and supported semantic assessment with zero issues are also required. These checks do not establish underlying-model independence or publication authority.
