# Bounded suggestion HTTP transport core

16 October 2026. B06-4a in the [suggestion sequence](../planning/13_B06_SUGGESTIONS_IMPLEMENTATION_PLAN.md) implements a pure backend HTTP adapter. It has no default runtime/provider, SDK import, package export or Next route. Public intake stays disabled. B06-4b runtime/configuration, route inventory and actual service/emulator HTTP integration remain required.

## Implemented boundary

Explicit strict configuration supplies enabled/intake flags and an exact HTTPS origin. Missing, malformed or disabled configuration returns a stable unavailable response before provider initialization. Disabling create leaves authorized status available. Exact versioned POST create and GET receipt-status paths dispatch only after validation. Unknown paths/methods and OPTIONS do not dispatch. The future DELETE withdrawal path returns unavailable before provider initialization; no withdrawal acknowledgement or mutation is invented ahead of B06-5.

Create requires a 64-character lowercase hexadecimal Idempotency-Key header, JSON URL-only payload and no Authorization header. Status requires only the receipt ID in the path and a fixed-format Bearer capability header, with no replay header. Merged/duplicate credential values fail validation. Missing/malformed status credentials and backend wrong/expired/revoked access use the same NOT_FOUND response. Tokens/replay keys are never accepted in navigation/query/body fields. Requests with URL query/hash/credentials, cookies, content encoding, wrong origin or cross-site metadata are rejected. No credentialed CORS or preflight allowance is added. Future first-party fetches must omit cookies explicitly.

Headers are capped at 32 and 8,192 encoded name/value bytes. The body is capped at 4,096 actual bytes, with bounded announced length and exact announced/received length matching when provided. Native stream reads enforce a deadline of at most five seconds, fatal UTF-8 decoding, JSON parsing and strict request validation. Abort/timeout cleanup does not wait on a caller-controlled cancellation promise. Parsed payload validation is strict; this packet makes no separate duplicate-JSON-key parser claim.

Backend/provider dispatch has a response deadline of at most ten seconds. A timed-out database operation may still commit: the response does not claim cancellation or definite submission failure. A future client must retain the same private replay credential and retry through the existing idempotency protocol. Successful outputs pass the separate create/status contracts, and status receipt identity must match the requested ID. Unknown/private fields or invalid outputs become unavailable.

Every response has private/no-store, no-cache, no-referrer, noindex/nofollow and nosniff headers, without cookies, redirects or CORS credential grants. Allowlisted domain failures map to stable public codes/statuses; raw SDK/parser/credential/source data is not returned. Prototype-named unexpected error codes cannot escape the allowlist.

Transport-rejected requests do not initialize/call the service and therefore do not consume its database attempt counters. Requests that reach create/status retain the backend's committed budgets. Edge-wide rejection/abuse controls remain required before exposure; this adapter does not provide them. The HTTPS-origin guard is intentionally conservative; explicitly guarded local emulator origin support and trusted deployment origin configuration belong to B06-4b.
