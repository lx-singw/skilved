# Citizenship and residence evidence guard

Date: 18 October 2026. Status: offline implementation following the [frozen V18 repeat](115_V18_REPEAT_AND_CITIZENSHIP_RESIDENCE_HOLD_2026-10-18.md). Recognised citizenship-only evidence now rejects a stated residence field during compact decoding and canonical mapping. Genuine explicit residence rules and correctly classified citizenship requirements remain supported. No source retrieval, provider call, publication or change to shared quota state is part of this sprint.

## Evidence boundary and integration

The shared check requires the residence quote to occur in the supplied title/article corpus. It then recognises a deliberately small set of citizenship-only clauses, such as a requirement to be a South African citizen, including simple citizenship/nationality labels, neutral requirement headings and list prefixes. A stated residence supported entirely by those clauses fails with `AI_RESIDENCE_EVIDENCE_UNRESOLVED`. Unsupported quote integrity remains the responsibility of the existing source-evidence checks.

Compact ordinary extraction and split metadata decoding apply the check before their result can be cached or stored as a candidate. Canonical mapping repeats it for internal/cached answers that bypass compact decoding. Programme decoding/mapping inherits the same guard without expanding its selected source scope. Rejection never replaces the residence field, changes a requirement, synthesises evidence or calls another model to repair the answer.

The guard is not a general residence classifier, residence completeness check or requirement-kind guard. Mixed citizenship-and-residence clauses, genuine residence rules, unfamiliar wording and ambiguous/conflicting fields remain for existing semantic/material review. Legal permanent-resident status is addressed in guidance but is not added to the narrow deterministic recogniser. Requirement strength, citizenship items, source evidence and application routes are unchanged.

## Guidance, versions and cache identity

Canonical, compact, metadata and programme extraction guidance distinguishes where applicants live from citizenship/nationality or legal status. It requires retaining citizenship as a citizenship requirement with its original strength and logic, leaving residence absent when no residence rule is stated, and preserving genuine mixed clauses without inferring a place. Full/programme validation and the requirements-only diagnostic inherit the same distinction. Validation also explicitly treats residence as optional when absent. A model's negative assessment remains negative; guidance does not override a verdict.

Changed contracts advance to extraction V19/compact V7, metadata V12, programme extraction V19, full validation V15, programme validation V14 and requirements-only diagnostic V3. Version changes separate future cache identities from older prompts. Output schemas, provider implementation, model chains, token/reasoning caps, source checklist expectations and application selection/binding remain unchanged. Old cache entries and failures are retained.
