## Explicit, bounded interpretation

The shared `organization-profile` adapter recognizes an exact HTTPS PNet posting URL and one unique, explicitly supplied organization URL in the observed `/cmp/en/<slug>-<id>/work.html` profile shape. Up to four identical claims can be preserved. It requires the known canonical host, bounded ASCII paths and positive numeric identifiers. The posting's full query is retained; the profile requires no query or fragment. No slug or ID is derived from an employer name, equated with a vacancy ID or treated as a grant.

The typed claim records `urlKind: platform_organization_profile` and `organizationProfile` with version `organization_profile_pnet_v1`, the exact observed posting URL and all literal organization URL claims. Malformed/unsafe/mixed-origin claims still fail the existing hint checks. Competing profile URLs and unrecognized shapes never gain the new interpretation. Calling the legacy hint API without an observation URL preserves its old result shape and host handling.

Worker origin receipts use `issuer_hint_v3` with method `platform_organization_profile` for this case; other hints keep their existing version/method. The claim is explicit evidence, not a discarded URL followed by a preferred domain guess. No new source option is needed: this operates only inside existing opted-in original/origin acquisition, with optional crawling and all current source/grant/lease/robots/network bounds intact.
