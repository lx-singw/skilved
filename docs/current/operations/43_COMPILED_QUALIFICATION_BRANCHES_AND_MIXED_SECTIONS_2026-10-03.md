## Source compilation and review contract

`mixed-review-policy.mjs` introduces `entry_applicability_v8`. Existing evidence constructors accept explicit supplements while preserving historical defaults. About the role/programme, Successful candidates and Employment Equity headings end minimum selection. An exact current application-document introduction can restart it after programme prose. Recruitment/deadline/enquiry transitions stop that list without hiding their text from the reviewer. Headings and the current document introduction are source-owned context constraints, not applicant conditions.

Explicit past-intake preparation retains its document checklist as one unresolved scope. Caveated introductions do not automatically restart current document selection. Repeated indistinguishable document headings abstain together if one is explicitly caveated. Unrecognized headings/prose remain semantic judgments; this is a narrow section policy, not universal applicability detection.

Only the already-recognized explicit candidate must-pass TVET-subject list followed by an OR vocational qualification and its contiguous course subjects becomes `compiledQualificationGroups`. Code owns those complete education spans, mandatory strength and OR membership **before** seeing any provider answer. No employer names, source audits or expected answers determine the rule. Incomplete, caveated or unfamiliar branches and other qualification alternatives remain model-owned.

`mixed-line-review.mjs` exposes `recentjobs_requirement_review_v12`. The model reads the complete numbered source but returns only the remaining keys, including all other protected evidence. Compiled branch keys are excluded from the exact local schema. Returning them, continuing into them or using them as an alternative anchor fails validation. Other source constraints are checked against the model answer without replacement. Code combines source-owned branches with validated residual passages, assigns distinct alternative groups and retains whole-source quote, coverage and logic checks. Compiled branches and residual model alternatives cannot share an internal group accidentally.

This is a change in ownership, not a repair of a defective model answer. Source-owned branches are reported separately from model-reviewed lines. Siemens has two compiled branches and 69 model keys instead of 78. The compact prompt schema stays 770 bytes. Bound contracts include source, policy, exact local schema and reasoning. Low remains the development default, with JSON-object output, the existing 3,072 completion-token cap and no retry/fallback. Worker extraction/validation settings are unchanged.
