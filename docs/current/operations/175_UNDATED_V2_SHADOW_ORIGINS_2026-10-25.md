# Recent-undated V2 shadow policy and persistent origins

25 October 2026. The first implementation step of the [undated-publication proposal](174_RECENT_UNDATED_PUBLICATION_PROPOSAL_2026-10-25.md) is available as a separate **`shadow_recent_v2` opt-in**. It supports narrowly unspecified closing dates, limits private review to six hours from acquisition and seven days from original publication, and stores persistent notice/original-route bindings. It cannot publish. Existing source configurations, V1 accepted drafts and their original expiries are unchanged.

## Admission and timing

Source configuration must explicitly select V2 in shadow mode, with an integer check TTL of at most six hours and source cadence no longer than that TTL. The default remains `reject`; existing `shadow_recent` behavior remains V1. A normal source revision is required when changing configuration; the implementation does not invalidate or clear historical source holds globally.

V2 accepts either no closing-date statement or one whole closing/deadline field whose value is exactly “not stated” or “not specified,” with bounded case, whitespace and separator/end-punctuation variants. A label/value split across adjacent source lines is supported. The entire bound notice and title are checked for competing timing. Relative, malformed, duplicate, conflicting, rolling, until-filled and other unsupported statements remain held. An application button does not establish a deadline or availability. Affirmative closure is rejected.

The canonical deadline remains `not_stated` with a null value. The private worker decision records whether timing was absent or explicitly unspecified and retains the exact source field as separate evidence. The application destination still comes from the original source method and qualified employer/delegated-route registry. Category, programme scope, material facts, original method, issuer, requirements, semantic validation and optional employer-crawl checks remain required.

Review expires at the earlier of acquisition plus the configured TTL and original publication plus seven days. Equality is expired. Validate the original publication instant, first acquisition and current acquisition/current time. An unchanged retry retains that job's first acquisition, so retries cannot renew an expired six-hour assessment. A genuinely new successful source-check job may obtain a new private check window within the immutable seven-day age ceiling. This is not a public renewal mechanism.

## Persistent origin binding

Before model work, an authorized worker transaction creates two private `worker_notice_origins` entries: one indexed by canonical publisher notice URL, the other by original application method/route identity. Portal identity uses origin and path without query parameters; email identity ignores case. Tracking changes cannot create a fresh route identity, while the full original destination remains unchanged in the stored binding and application action. Query-selected intakes sharing a portal path are conservatively held for explicit identity review. Both entries contain the same versioned origin: source ID, URL, source title, qualified issuer, full method/destination, original publication, first-seen instant and first content hash. Both keys are independent of job IDs and source revisions. Creation is atomic; concurrent jobs cannot independently establish conflicting origins.

Subsequent jobs must match the stored binding. Changed publication time, title, source ID, issuer, route or a different URL sharing that route is held for identity review. This is deliberately conservative: shared generic portals/emails or apparent reposts cannot automatically establish a new intake. Body corrections and material changes retain the original age; source revision changes do not reset it. The implementation does not claim that a title alone proves employer intake identity. Broader duplicate/intake resolution still needs qualification.

Unchanged content can reuse the existing source/revision/model/contract-bound extraction and validation caches. Changed content invokes reassessment through the ordinary cache key; a failed reassessment does not renew the accepted draft/decision. Existing sticky withdrawal/withholding, source pause, grants, lease and revision checks remain in force. Both stored origin copies and timing are rechecked inside the draft commit. Missing, inconsistent or changed origin data fails closed; the worker never deletes origins to obtain a fresh window.

There is no accepted-record migration, expiry extension, source-cap increase, quota reset, hold/cache deletion or model-default change in this sprint. Provider failures remain spent, and daily exhaustion remains shared across jobs. Employer crawling remains optional/off.

## Remaining work

This implements the shadow admission/origin foundation. Origin history starts at the first V2 binding; importing earlier V1/history acquisitions is not implemented. Previously seen sources need reviewed original-publication/first-seen history before real V2 onboarding; a new fetch alone cannot detect retiming that predates its first binding. No actual source is opted into V2 by this sprint. Public undated visibility, maintenance watches, cross-surface expiry/renewal behavior, applicant-facing availability disclosures and deployed scheduler capacity remain unimplemented/unqualified. Automatic publication still requires a future stated date; Gemini remains shadow-only.

Next freeze a broader current source cohort for genuinely unseen 3.5 Flash-Lite evaluation, qualify its original application relationships and source checklists before generation, and exercise V2 on repeated source changes in shadow mode. Public projection/handoff and maintenance qualification from the proposal must precede any automatic undated enablement. Production scheduling/publication remains disabled.
