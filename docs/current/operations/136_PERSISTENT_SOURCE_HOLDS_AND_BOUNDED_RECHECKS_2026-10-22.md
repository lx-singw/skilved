# Persistent source holds and bounded rechecks

Date: 22 October 2026. Status: the worker now remembers deterministic source failures across jobs and restarts. For a notice without public history, a matching hold skips detail retrieval for up to twenty-four hours before becoming eligible for a scheduled recheck. Existing jobs, exceptions and evidence remain intact. Model retries, provider exhaustion and publication freshness retain their existing policies.

## Worker behavior

The [current cohort screen](135_CURRENT_COHORT_RECHECK_AND_UNCHANGED_SOURCE_HOLDS_2026-10-22.md), committed as `8088511`, is minutes old when this sprint begins. Repeating those source requests would provide little new evidence. Review instead identifies that discovery queues the same held detail again on every source cadence, including when source facts and policy have not changed.

Terminal source failures now write a private `worker_holds` entry keyed by source and detail URL. It records the failure reason, source revision, hold-policy version, programme-extraction mode, original job, snapshot/content hash when available, observation time and recheck time. Hold creation is limited to deterministic preflight failures: unsupported/conflicting category evidence, imprecise date or method, closed/closing-day notices, physical application instructions and unsupported programme subjects. The strict detail-layout rejection can also create a hold without inventing a parsed candidate or snapshot.

Before requesting detail robots or HTML, a later detail job checks this entry under the existing machine grant and source lease. A matching active hold completes that later job with an explicit `sourceHeld` result and original-exception reference. The original failed job stays closed; its exception and snapshot are neither overwritten nor reopened. Discovery still retrieves its listing on the source cadence so that new URLs can enter the queue.

A hold becomes inapplicable at its exact expiry, after a source-policy revision, when programme-extraction mode changes, or when the code's hold-policy version changes. Invalid identity, unsupported reasons, obsolete versions and holds exceeding twenty-four hours cannot suppress retrieval. A source/parser change that should release holds must also bump the private hold-policy version. No permanent exclusion is inferred from a closed date, missing information or a layout failure.

Published records retain their existing freshness path. Failures on notices with public history do not create source holds, and a live published-record watch bypasses any saved hold. No hold renews an opportunity's checks or changes its public availability. Model rejections, semantic failures, network errors, source budgets and Gemini availability/rate-limit handling do not use this source-hold mechanism. No spent reservation is refunded.

Authenticated reviewers can inspect and paginate `worker_holds` through the existing operator methods; ordinary clients receive no new access. Shadow CLI reports include the collection so that new private reports can preserve it across replay/restoration. An entry is the latest hold index; the original per-job exceptions and snapshots remain the evidence history. Historical exceptions are not automatically backfilled into holds.

## Limits and next work

The worker cannot observe edits to a held detail page while skipping its retrieval. Corrections become visible after expiry or another release condition; actual retrieval still follows the source's scheduling cadence. The twenty-four-hour hold trades prompt detection of corrections for fewer repeated requests. It does not prove that a page is unchanged or resolve missing source facts. Previously held notices require their next actual source failure to populate the new index.

This sprint uses the recent saved cohort rather than another live crawl. No production source configuration, provider quota, model cache, draft or public record is changed. Gemini remains shadow-only, employer crawling remains optional/off, and production scheduling/publication remain disabled. Next assess a genuinely new or changed eligible apprenticeship under the existing source checklist and model limits, preserving this hold history alongside the quota ledger.
