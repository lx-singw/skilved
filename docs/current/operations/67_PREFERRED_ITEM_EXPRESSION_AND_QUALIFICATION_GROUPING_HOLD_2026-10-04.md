## Preference strength and expression grammar

The shared extraction/audit instruction makes the existing contract explicit: every item retains its required/preferred level and a reference in the expression. The expression inventories source relationships; it does not evaluate an applicant's eligibility. Independent preferred items use ordinary references under ALL, with level preferred retained. That inventory does not promote them to mandatory requirements.

The compact prompt supplies the example all(any(r1,r2),r3,r4) for required alternatives r1/r2 and independent preferred items r3/r4. ANY still means a real source alternative. The token none remains legal only for an unstated IF otherwise branch; it cannot stand alone or create an ANY/ALL child. Preferences cannot be omitted or represented by invented optional alternatives, conditional predicates, empty items or unknown passages.

The independent validator receives the same strength semantics and audits each item's level against the source. It must still reject changed strengths, invented conditions and unsupported alternatives. Existing semantic support, source attribution, exact original application routes and material uncertainty checks remain required.
