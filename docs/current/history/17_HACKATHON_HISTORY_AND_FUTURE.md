# Hackathon history, demonstrations and future competition readiness

Date: 11 September 2026. Status: historical reconciliation and optional future competition plan.

## What is established

The founder says the initial hackathon project was not finished in time and wants to develop Skilved as a startup. Legacy documents refer to an XPRIZE strategy and an eight-week sprint calendar. This refresh has not verified the original competition's rules, final deadline, submission or results. No new competition has been identified by the founder.

The startup roadmap therefore has no invented hackathon deadline. Keep a future competition as an optional demonstration/distribution opportunity; it cannot redefine user permission, trust or financial reality.

## Prototype status vocabulary

| State | Meaning | Permitted demonstration claim |
|---|---|---|
| Planned | Only a document, interface or stub exists | Explain the intended flow |
| Synthetic demonstration | Uses clearly labelled fictional records/results | Demonstrates interaction or format, not operational capability |
| Implemented locally | Actual code runs against local/emulated dependencies | State the environment and limits |
| Integrated test | Real permitted source/service succeeds under defined conditions | Describe the tested route, not universal coverage |
| Pilot used | A real consenting participant completes a task | Report the task and observed result accurately |
| Production operated | Deployed with controls, support, recovery and monitoring | Report measured availability/quality over the actual period |

The existing profile/feed UI provides reuse opportunities, but source fixtures, in-memory identity and hardcoded verification do not satisfy integrated or production states. The September 5 MVP review was a static inspection, not a passed production test. The current September 11 planning refresh is also documentation work.

## Optional future competition track

Activate this track only after a real competition is chosen. Its time comes from the same capacity as product work; it is not free additional labour.

| Step | Work | Evidence / dependency |
|---|---|---|
| C0 — Fit | Read official rules, judging criteria, eligibility, dates, IP and data conditions | Dated rules summary and founder decision to enter |
| C1 — Demonstration slice | Choose an already useful connected workflow and a truthful stretch capability | Scope tied to actual sprint packages |
| C2 — Reproducibility | Prepare labelled fixtures and permitted live inputs; document environment and known failures | Rehearsal recording/logs, offline fallback labelled as such |
| C3 — Evaluation | Compare relevant baselines, measure quality/time/cost and disclose limitations | Benchmark report with actual results |
| C4 — Narrative | Explain user problem, real experience, differentiation hypothesis and next evidence | Pitch, architecture, demo script and evidence appendix |
| C5 — Submission | Check exact format/deadline/accessibility and obtain any needed participant permissions | Complete package reviewed against official checklist |
| C6 — Follow-through | Capture feedback, honour participant commitments and return to business validation | Updated decision register and next sprint |

Suggested demonstration: discover a real opportunity, show its source, create a reviewed requirement checklist, select genuine or clearly fictional evidence, pause for a missing item, resume the task after an update, prepare a pack and hand off externally. A second scene can show a nominated supervisor confirming a specific contribution when actually available. Never present a pre-recorded confirmation as live autonomous work.

A competition demo can omit mature institutional infrastructure if the omission is disclosed. It cannot omit correctness, consent or truthful status while claiming the complete production service.

## Current pitch narrative to develop from evidence

**Problem:** people repeatedly assemble fragmented career information and struggle to move from an opportunity to a prepared next step. Helpers and programme staff may repeat the same collection and follow-up work.

**Product:** a living career record connected to opportunities, persistent assistance and structured support, useful across existing platforms.

**First audience:** apprentice peers and school leavers; public product supports all six categories.

**Differentiation to prove:** reusable evidence, source-backed preparation, resolution of practical obstacles, recipient acceptance and lower coordinator effort.

**Traction today:** founder reports interest from conversations. No payment, active-user total, placement improvement or external partnership is established by this documentation.

**Next evidence:** real task completion, useful return visits, recipient use, measured delivery costs and an actual customer purchase/renewal decision.
