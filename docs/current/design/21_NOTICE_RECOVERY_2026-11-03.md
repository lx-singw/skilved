# Notice recovery and interrupted journeys

Implemented: 3 November 2026.

Missing pages, page errors and unavailable opportunity details now use a shared notice-file layout. A compact index, folded-corner document mark, status-specific opening and ruled reading ledger extend the sage/forest workspace into recovery. The screen records what is known, explains a next step and offers routes to the feed, browser-local Saved references and the public field guide. It introduces no automatic retry, storage mutation, new production route or application action.

The states remain separate. A failed detail read does not establish closure or removal. Under-review notices say that the listing needs a fresh check without claiming that the issuer has closed intake. Withdrawn and archived projections say the listing is no longer published on Skilved without inventing issuer dates. Missing pages describe an address that could not be found without deciding why. Page errors expose no error message or digest in the rendered screen.

The unavailable-detail retry is a native link that requests the same notice again. Validated catalogue filters and cursor context return through the existing `catalogueReturnHref` boundary, including the original card fragment. External, malformed, unsupported and repeated return contexts fall back to the feed and are omitted from the retry URL. Review, withdrawn and archived states have no retry or application action. The page error uses Next’s explicit reset callback only when the button is activated. Saved guidance retains browser-only storage, lack of backup/sync and the distinction between a saved reference and a current notice copy.

Verification passed in order: web lint, typecheck, production build, then all 286 web tests against that fresh build. Four new component tests cover return-context rejection, manual same-notice retry, unavailable application actions, accessible structure, local-storage wording and explicit error reset. A new production HTTP test confirms a real missing route retains HTTP 404 and provides truthful recovery exits.

Browser checks covered the unavailable, under-review and withdrawn examples, keyboard navigation between examples and the actual missing-page route. The desktop document had no horizontal overflow. At a measured 389 CSS-pixel viewport, client and scroll width both measured 370 pixels, no main-content elements exceeded those bounds, and all main links measured at least 44 pixels high. The temporary viewport override was reset. Screenshot capture failed; screenshot-based visual review remains incomplete. Page-error reset was tested through its callback rather than by injecting a browser error. Archived wording shares the unpublished layout and was covered by rendered tests.

The previous isolated preview process was already stopped. Only the Next UI server was restored, with catalogue reads, reports, suggestions and AI disabled; no emulator was reseeded and no saved data or private receipts were cleared. A private, ignored `/ui-preview/notice-recovery` route labels its states as local UI examples, not real listing statuses. The isolated preview received the shared recovery source and selective detail-page branch updates while retaining earlier private preview overrides. No fixture route or example status was committed. Production deployment, a live catalogue connection and screenshot visual assurance were not verified.
