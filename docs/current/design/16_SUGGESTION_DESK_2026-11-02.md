# Suggestion desk and private receipts

Implemented: 2 November 2026.

The suggestion page now uses a contribution desk with a public-notice form, compact browser-access guidance, a separate reading guide and a private receipt file. The existing unavailable and paused-intake states remain visible and control the same actions. Returning users with local entries can jump directly to their receipt section. An empty readable list no longer offers a pointless clear action; unreadable access still has its explicit discard path.

Address feedback uses the existing conservative SuggestionUrlSchema. It checks format locally without fetching a source, deciding publicness or promising support. A usable format shows only the hostname outside the editable field. Invalid input remains intact and carries aria-invalid plus descriptive guidance. Query strings, fragments, credentials and other unsupported syntax are not silently stripped. The form remains disabled until its format, service settings and local storage are ready.

Failed, ignored and obsolete attempts now retain their entered link. The internal session action returns a completion boolean only for a confirmed submit or explicit retry outcome. The form clears only the matching original input after that signal; a newer edit is retained. An exact canonical match to an existing draft or live pending entry directs the user to Retry this entry instead of starting a duplicate submit. Expired pending entries do not block a separate submission. Successful recovery of the matching entry can clear its old input without clearing another address.

Receipt presentation distinguishes not submitted, no recorded send attempt, unconfirmed submission response, saved private access and expired access. Local save time, access or retry expiry, and the server update in the last explicitly checked response have separate labels. Public result references lead to current opportunity details. No review completion bar, application confirmation or response-time promise is inferred.

The display model excludes source URLs, local IDs, replay tickets, receipt IDs and capabilities. Ordinal receipt labels are used in the DOM. Status still refreshes only through its explicit action. Paused intake disables new suggestions and retries while eligible status and withdrawal actions remain available; expired access disables server actions while retaining local forget. No persistence schema, transport header, replay protocol or backend setting was changed.

Discard and withdrawal retain their different confirmations and the observed access token. A selected entry's confirmation now appears beside that entry rather than after the whole list. Local forget or clear still sends no withdrawal request, and server withdrawal still needs acknowledgement. Receipt access remains separate from saved opportunity progress.

Verification passed: typecheck, lint, production build and all 247 web tests. Ten new tests cover exact URL-contract parity without network use, canonical retry matching and expiry, secret-free state presentation, action gates, completion signals and obsolete responses, failed-input retention, newer edits, response-loss recovery through the same stored ticket with actual fake IndexedDB, adjacent confirmation with the captured token, and loading/error/empty/paused states. Existing suggestion UI tests now use the shared loader for the extracted view dependencies and retain their privacy and access checks.

Browser review confirmed that ordinary local intake is unavailable and correctly disables the form. A clearly marked form-only override in the ignored preview checkout enabled input checks without configuring the intake API. HTTP and query-bearing examples stayed blocked; the query text remained unchanged. A clean fictional HTTPS example showed format-only feedback and the hostname. No form was submitted.

At a measured 389 CSS-pixel viewport, both form and fictional receipt layouts had document scroll width equal to the 370-pixel client width and no visible content overflow. Keyboard Enter opened the browser-access disclosure. Separate fictional display samples covered draft, unsent, pending response, saved access, returned public references and expiry; they did not enter the private ledger. Expired server controls were disabled while local forget remained available. Sample DOM checks found no hidden local identifiers or ticket text. Desktop form and receipt layouts were reviewed and screenshots saved outside the repository. Final form recapture failed after viewport testing; the updated receipt screenshot remained usable. Temporary viewport sizing was reset.

The form override and sample route exist only in the ignored local preview. Backend review intake remains disabled there. No live suggestion, withdrawal, receipt discard or clear was performed, and saved opportunity progress was not changed. Synthetic transport responses cover submit and retry behaviour; live intake integration, production deployment and broader user research remain separate.
