# Saved records inside the opportunity feed

Implemented: 3 November 2026.

Saved feed cards now include a small personal record beneath their reading actions. A bookmark tab separates the public notice from browser-local progress. The record shows the person’s stage, a scoped explanation and the original saved time in the browser’s timezone. It uses the existing category colour variables and ruled notice layout. On narrow screens the stage and return section stack vertically.

The four stages retain their meanings. Interested returns to the story, Preparing returns to requirements with a reminder that ticks are temporary, Applied is explicitly a personal report without confirmed submission, and No longer pursuing remains separate from listing status. A differing revision directs the person to read the current details while retaining their stage. Closed intakes offer a reading link instead of a preparation shortcut. No route action, review acknowledgement or stage change is inferred from opening these links. Canonical public return filters remain attached to feed links; personal stages and times are not added to URLs.

Save is now a one-way explicit action on an unsaved feed card. Once confirmed, the control becomes a link to that notice’s personal workspace. Clicking it no longer removes the saved item or its history. The existing explicit removal controls in Saved and the notice workspace remain available. The shared detail-page rail uses the same control in compact form with a same-page fragment, retaining its existing return-query context.

Unknown storage is not shown as a confirmed unsaved state. Loading disables Save; unavailable, unreadable, conflicting, full and unconfirmed results provide tailored guidance, manual reload and a link to Saved. Unreadable formats are not reset, failures are not automatically retried and no clear operation is introduced. All mutations continue through the existing local progress session and its transaction-confirmed snapshots. The live status reports the initiating operation. After confirmation, focus can move from the replaced Save button to the Saved link, provided the person has not moved to another control. Background refreshes do not request focus.

Verification: web lint, typecheck, production build and all 292 web tests passed against the final build. Six new tests cover stage-specific routes and boundaries, differing revisions in either direction, closed-intake links, storage recovery without mutation, confirmation/focus behaviour and real card/rail integration. The earlier feed save test now checks the explicit save action and subsequent manage link rather than toggle removal.

Browser verification used the real control on an isolated `127.0.0.1` origin and a fictional local example. Keyboard activation produced a confirmed saved record and moved focus to its manage link. The existing localhost saved list was not changed. The six illustrative stage/revision/intake records are view-only and separately labelled; they are not personal history. Desktop and narrow screenshot review succeeded. At measured 300 and 390 CSS-pixel widths, document scroll width equalled client width, no main-content elements overflowed horizontally at the narrower width, and the saved-record links measured 44 pixels high. The viewport override was reset.

The ignored card workshop received the new components and styles without reseeding the catalogue or changing service flags. It uses a projected fictional public fixture and is not a production route. The example’s canonical detail links do not resolve to real opportunities. No private receipt, report, suggestion, application or source visit was performed. Live catalogue connectivity, dark-mode screenshot review and production deployment were not verified in this sprint.
