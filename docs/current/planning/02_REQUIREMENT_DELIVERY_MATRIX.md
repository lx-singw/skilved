# Requirement-to-delivery matrix

13 September launch revision: this remains the expanded allocation of 64 requirements. The [M0 scope table](../product/03_DISCOVERY_FIRST_MVP.md) identifies partial requirement/package slices delivered for the discovery-first public MVP. Completion of M0 is not completion of every mapped requirement. Reforecast package allocation after S01 without counting the same work twice.

Date: 11 September 2026. Status: complete initial planning allocation, not implementation status. The [PRD](../product/02_PRODUCT_REQUIREMENTS.md) owns acceptance wording; the [backlog](16_SPRINT_BACKLOG.md) owns work-package content and the [roadmap](15_BUILD_ROADMAP.md) owns numerical estimates.

A requirement may begin as a small usable capability and mature in a later package. The public MVP still includes every confirmed category. Relevant age/privacy/source-access gates apply before the affected use, even if a later package develops richer functionality. These mappings organise inclusive effort; they do not add a second estimate for the same work.

## Implementation use

Create scoped issues with the linked requirement, package, acceptance and actual evidence. Use the [test catalogue](../quality/01_TEST_CASE_CATALOGUE.md), [security assurance](../security/04_SECURITY_ASSURANCE_REGISTER.md) and [design QA](../design/04_ACCESSIBILITY_AND_DESIGN_QA.md) for representative checks, then add cases for the adopted implementation. Do not infer completion from this allocation.

For PRD-033, R3 includes the small change from applying to onboarding goals and suppression of irrelevant reminders; S20 expands the programme lifecycle. For PRD-046/047, S17's manual pilots test recipient/assessment acceptance before S21/S19 automation. For PRD-053, S20 must include the agreed renewal requirements where a programme needs them; credential validity handling matures in S23. Sponsored listings under PRD-063 are conditional and must not launch until their labelling and quality controls exist.

If any allocation needs material work beyond its package range, record the scope change and revise the roadmap. Partner waiting time is not hidden inside an assumed two-week sprint.
